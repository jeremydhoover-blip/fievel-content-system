# Designing behavior

Reviewed: 2026-10-21. Original Fievel teaching text; references are not organizational policy.

Behavior rules describe when an assistant explains, asks, acts or hands off. A tool is a capability, not permission to use it.

Example: Without a cancellation tool, explain the next step rather than claim success.

Common mistakes: Writing only tone rules; asking for confirmation for every harmless explanation.

Try it: Write one action boundary and one recovery message.

Related concepts: Tool calling; confirmation; uncertainty.

Reference: https://github.com/modelcontextprotocol/servers
