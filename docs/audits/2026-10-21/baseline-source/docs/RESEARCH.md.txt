# Focused research and reuse decisions

Reviewed **2026-10-21** against public primary sources. Scope: a working,
repository-native first slice with no required model API or external connectors.
We inspected project READMEs, documentation, license declarations and public GitHub
metadata. [repository-snapshot.json](repository-snapshot.json) records actual
pushed_at, archive state and license classification from the GitHub API. A push
date is an activity signal, not proof of a support commitment or implementation quality.

No upstream implementation or training scenario was copied. Fievel's workflows,
example and teaching text are original. Links are references; they do not extend
Fievel's license to third-party content. Recheck file-level licenses and notices
before incorporating any upstream code in later releases.

## Evaluation design findings

The [eval-guide workflow](https://github.com/microsoft/eval-guide#skills) distinguishes
design work from a run against a real agent. Fievel preserves that boundary:
definitions alone never produce pass results. The
[scenario library](https://github.com/microsoft/ai-agent-eval-scenario-library#two-types-of-scenarios)
distinguishes task outcomes from underlying capabilities. Wayfarer includes both
booking support tasks and evidence/action-boundary questions.

[Promptfoo assertions](https://www.promptfoo.dev/docs/configuration/expected-outputs/)
offer deterministic and model-graded methods. Fievel's initial contract is smaller:
contains, not_contains and human. This is not a Promptfoo-compatible configuration
or a claim that Promptfoo ran. A future adapter needs explicit provider selection,
credential handling, provenance, assertion mapping and grader validation tests.

[Vale styles](https://docs.vale.sh/topics/styles) separate rule type, scope and
feedback. Exporting approved terminology to Vale is preferable to extending our
substring checker into a homemade language linter. Vale is not installed or tested.

## Agent-host compatibility findings

| Environment | Official guidance checked | Implementation choice | Actual validation |
|---|---|---|---|
| Codex | [Project instructions](https://developers.openai.com/codex/guides/agents-md/), [skills](https://developers.openai.com/codex/skills/) | AGENTS.md and .agents/skills; explicit read prompt fallback | Files inspected and local commands tested from this Codex session; fresh-session automatic loading/conversation not tested |
| Claude Code | [Skills](https://code.claude.com/docs/en/skills) | CLAUDE.md pointer and generated .claude/skills copies | Static synchronization only; runtime unavailable/unverified |
| VS Code agent | [Agent Skills](https://code.visualstudio.com/docs/agent-customization/agent-skills) | Copilot instructions pointer and canonical .agents skills | Static assets only; runtime unavailable/unverified |

Official documentation describes these discovery paths, but existing host sessions
can cache skill inventories and different agents/extensions may behave differently.
Adapters therefore include an explicit-read route; do not market them as tested
cross-platform support. No model-specific API, API key or custom MCP setup is required.

## Reuse and dependency decision

Use Python's standard library for portable file operations, CLI parsing, hashing
and tests. Reuse [python-jsonschema](https://github.com/python-jsonschema/jsonschema)
(MIT) for Draft 2020-12 instead of inventing a partial validator. requirements.txt
pins the directly used version; transitive resolution is not fully locked yet.
The locally installed distribution includes its upstream license notices in .deps;
dependencies are not vendored or committed. No other researched tool is a runtime
dependency. Full upstream code audits and runtime integration validation remain
prerequisites to any future incorporation.
