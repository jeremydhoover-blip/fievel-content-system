# Knowledge architecture and instruction quality

Status: initial content architecture, 2026-10-21. The bundled library is a product
capability. It is not a cache of whichever web pages the agent last visited.

## Distinct layers and authority

| Layer | Examples | Authority and use |
|---|---|---|
| Fievel behavior | AGENTS.md and workflow skills | Guides Fievel's workflow within the host/user instruction hierarchy |
| Bundled educational library | Concepts, procedures, examples, exercises | Explains how to design; cannot approve or replace company policy |
| User content system | Product, standards, behavior, checks, governance | Records the designer's decisions and approval labels; distinguish drafts |
| Organizational evidence | Authorized local style guides/policies/examples | Source authority, scope, dates and interpretation must be assessed |
| Current external references | Tool docs, standards, new research | Verify when needed; record date/limitations; not silently imported as policy |
| Consuming AI instructions | A reviewed composition of relevant context/rules | Must be deliberately integrated and behavior-tested; files alone enforce nothing |

## Content types and routing

Use four needs, informed by Diátaxis: a guided practice activity, a task procedure,
a precise reference and an explanation. Do not mix an extended theory lesson into
every operational step. Beginners can learn alongside a real action; experienced
users can follow the procedure and open rationale when useful.

knowledge/INDEX.md is the task router. It identifies which small module answers
the current need; the agent reads that module, not the entire library. Each useful
module has: objective/audience; concise explanation/procedure; technical terms;
worked example; a mistake or limit; exercise; a way to judge the exercise; related
topics; primary-source references; reviewed date and currency caveat.

The new modules on system relationships, existing guidelines and instructions/skills
start filling gaps in the current path. They are original draft teaching text,
not a reviewed curriculum. Four short legacy modules remain introductory and need
expansion. Do not label the library comprehensive because a navigation file exists.

## Offline-first policy

For a covered foundational question: load the bundled module and fictional
example; explain from those; disclose gaps when material is insufficient.
For a company policy: inspect only authorized supplied/local evidence. If absent,
keep the policy unknown. General web material is not a substitute for company approval.
For current host/API/tool behavior: verify current official documentation when
needed and available; say when offline material cannot establish the current fact.
For a new topic: identify the gap, research deliberately if authorized, and propose
a sourced library improvement rather than silently treating one retrieval as curated.

“Offline-first” means the core concepts and exercise need no network fetch. It
does not mean timeless accuracy, host access without an account, or a guarantee
that a compatible coding agent itself works offline.

## Bring-your-own-guidelines workflow

1. Identify the user's task and the material they want used; inspect scope and access.
2. Inventory the source separately from ingestion. Keep unknown owner/date explicit.
3. Extract a small number of candidate standards with exact locators or short
   permitted excerpts. Distinguish explicit requirement, example, preference and
   inferred recommendation.
4. Show a source→proposed-rule mapping in the conversation/viewer. Preserve meaning
   and recorded approval; ask for a decision when interpretation changes authority
   or conflicts cannot be resolved from evidence.
5. Record agreed rules and unresolved questions; link suitable checks. Do not let
   pressure for a complete package manufacture missing organizational policy.
6. Compose/integrate instructions only for a named consumer and tested scope.
   Show what is included/excluded and evaluate actual behavior, not just file syntax.

Exact evidence locators and approval provenance need a schema proposal before
machine enforcement or a richer viewer can claim to verify them. The current
source_ids link is useful but weaker than this intended quality contract.

## Quality and maintenance

Curated entries need a content owner/reviewer and source-currency classification.
Review foundational material when misconceptions or exercises fail; review
version-sensitive references when their target changes or before relying on them.
Dates record the inspection performed, not a guarantee of continuing correctness.
Check broken links locally without treating link existence as factual review.

Before accepting a lesson, have a domain reviewer assess accuracy and an intended
learner complete its exercise/teach-back. Before accepting a skill, test routing,
input gaps, produced artifacts, errors and resumption in clean contexts. Before
accepting generated consumer instructions, test against source-bound pass/fail
situations. Keep human judgments, agent suggestions and deterministic checks distinct.

No vector database, custom retrieval service or mass documentation mirror is
needed yet. Revisit search/indexing when observed retrieval failures justify it.
Preserve source licenses; author concise teaching material instead of copying whole
external manuals. Registry metadata and local routing are maintenance aids, not
proof that a lesson has been reviewed by an independent expert.
