# Practice with Wayfarer

Read product.json, then handbook.md. All policies and transcripts are fictional.
The files show a drafted seven-stage package, not an approved production system.

1. Ask Fievel to explain the link from behavior-1 to payment-unknown.
2. Run the checks using the good saved responses in ../responses-good.json.
3. Create a human review sheet; read each response alongside its situation/context.
4. Try ../responses-bad.json and inspect the deliberate failures.
5. Improve a draft rule, record the decision in governance.json and progress.json,
   then rerun to a new report. A changed rule does not retroactively update old results.

The good fixture contains one invented policy claim that literal checks cannot
detect: see refund-status. It is deliberately a teaching case for human review.
